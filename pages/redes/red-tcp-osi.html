Fundamentos de Redes

TCP/IP · Modelo OSI · Tipos de red

¿Que es una red informatica? Un enlace a traves del cual dos o mas dispositivos se comunican mediante medios fisicos o inalambricos para intercambiar datos. La red domestica tipica: Proveedor de Internet → Router/Modem (procesa y redirige paquetes) → dispositivos conectados.

Mnemonico OSI (7→1) "All People Seem To Need Data Processing" → Application, Presentation, Session, Transport, Network, Data-link, Physical. En español: "Para Suele Trabajar Nuestra Enseñanza De La Física". TCP/IP se remonta a 1972 cuando el Departamento de Defensa de EE.UU. lo uso para enlazar su red.
Contenido de los paquetes de red Cada paquete contiene Cabecera (Direcciones MAC + Direcciones IP + Puertos) + Datos + CRC (Comprobacion de Redundancia Ciclica para deteccion de errores). El overhead es toda la informacion adicional a los datos puros.

Redes inalambricas vs cableadas Las redes cableadas poseen mayor tasa de transferencia de datos y mayor seguridad. Las inalambricas admiten mas tipos de dispositivos. Toda red inalambrica moderna tiene como base una interconexion de dispositivos cableados.

TCP vs UDP — Comparativa de Protocolos de Transporte
Fiabilidad · orden · velocidad · cuando usar cada uno
▼

TCP y UDP son los dos protocolos de la capa de transporte de la pila TCP/IP. TCP prioriza la fiabilidad y UDP prioriza la velocidad.

CaracteristicaTCPUDP
Orientado a conexionSi (handshake 3 vias)No (envio directo)
FiabilidadAlta — confirma y reintentaBaja — sin confirmacion
Orden de paquetesGarantizado (reordenacion)No garantizado
Control de flujo / congestiónSiNo
VelocidadMas lenta (overhead)Mas rapida (sin overhead)
Cabecera20-60 bytes8 bytes
Peso / sobrecargaAltoMinimo
Ejemplos de usoHTTP/HTTPS, FTP, SSH, correo, DNS (TCP)Streaming, VoIP, gaming, DNS (UDP), DHCP
Regla practica Usa TCP cuando no puedas perder ni un dato (web, archivos, correo). Usa UDP cuando priorices la velocidad en tiempo real y puedas tolerar perdida ocasional (video llamada, juego online).

DNS — Sistema de Nombres de Dominio (en profundidad)
Como traduce nombres · tipos de registro · resolucion completa
▼

El DNS (Domain Name System) es "la guia telefonica de Internet": convierte nombres faciles de recordar (www.google.com) en direcciones IP. Sin DNS, tendriamos que memorizar numeros para cada sitio.

Tipos de registro DNS

RegistroFuncionEjemplo
ANombre → IPv4www → 142.250.217.14
AAAANombre → IPv6www → 2a00:1450:4001:82d::200e
CNAMEAlias de otro nombrewww → mi-dominio.com
MXServidor de correo del dominiomail.mi-dominio.com (prioridad 10)
NSServidores DNS autoritativosns1.mi-host.com
PTRIPv4 → nombre (resolucion inversa)14.217.250.142 → www
TXTTexto / verificaciones (SPF, DKIM)v=spf1 include:provider.com
SRVServicio especifico (VOIP, AD)_sip._tcp.mi-dominio.com
Resolucion en 4 pasos 1) Tu equipo pregunta al resolver (tu router o ISP). 2) El resolver consulta la raiz "." y luego el TLD (.com). 3) El TLD apunta al servidor autoritativo del dominio. 4) El autoritativo devuelve la IP (registro A). La respuesta se cachea (TTL) para acelerar consultas futuras.
DNS publico recomendado El DNS de tu ISP puede ser lento o censurado. Alternativas seguras: Cloudflare 1.1.1.1 / 1.0.0.1, Google 8.8.8.8 / 8.8.4.4, Quad9 9.9.9.9 (bloquea sitios maliciosos). En Windows: Panel de control → Adaptador de red → IPv4 → servidores DNS.
DHCP — Asignacion Automatica de IP (en profundidad)
Ciclo DORA · concesiones · reservas · como configurarlo
▼

DHCP (Dynamic Host Configuration Protocol) asigna direcciones IP, mascara, gateway y DNS de forma automatica. Sin el, habria que configurar cada dispositivo a mano.

PasoSiglaQuienQue hace
1D — DiscoverClienteBusca un servidor DHCP ("hay alguien?")
2O — OfferServidorOfrece una IP disponible y parametros
3R — RequestClienteAcepta la IP ofrecida
4A — AckServidorConfirma la concesion (lease)
Ciclo DORA — Cliente ⇄ Servidor
Un ping-pong de 4 mensajes para obtener una IP automaticamente
1
Discover — el equipo grita
El cliente envia un broadcast a la red buscando cualquier servidor DHCP disponible.
broadcast 255.255.255.255:67
2
Offer — el servidor responde
El servidor reserva una IP y la ofrece con mascara, gateway y DNS junto al tiempo de concesion.
respuesta UDP:68
3
Request — el cliente acepta
El equipo solicita formalmente la IP ofrecida (para que el servidor la confirme y se la asegure).
unicast a un servidor
4
Ack — concesion confirmada
El servidor confirma con un ACK. El equipo ya tiene IP valida por el tiempo del lease.
lease tipico: 24h
Reservas DHCP Para que un dispositivo (impresora, servidor, NAS) tenga SIEMPRE la misma IP, configura una reserva: vincula la direccion MAC del equipo a una IP fija en el router. Es mas solida que poner una IP estatica manual (evita conflictos).
Tiempo de concesion (lease) La IP se alquila por un tiempo (tipico 24h). Al vencer, el dispositivo la renueva si sigue conectado o la libera. Un lease corto libera IPs rapido (ideal redes con muchos clientes moviles); uno largo es mejor para redes estables.
VLAN — Redes Locales Virtuales
Segmentacion logica · beneficios · ejemplo de configuracion
▼

Una VLAN separa una red fisica en varias redes logicas sin cambiar cables. Un switch con VLAN 10 (Ventas) y VLAN 20 (TI) mantiene el trafico aislado aunque compartan el mismo equipo.

BeneficioExplicacion
SeguridadDepartamentos aislados: Ventas no ve trafico de TI
Menos broadcastReduce el dominio de broadcast, mejora rendimiento
FlexibilidadMueves equipos sin recablear: cambias la VLAN del puerto
OrganizacionPor departamento, por tipo de dispositivo o por nivel de acceso
VLANs en switch gestionable (Cisco-ish)
Switch(config)# vlan 10
Switch(config-vlan)# name VENTAS
Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport access vlan 10
Trunking (802.1Q) Cuando varias VLANs viajan por el mismo cable hacia otro switch o router, se usan puertos trunk con etiquetado 802.1Q. Asi un solo enlace transporta multiples VLANs.

Rendimiento — Ancho de Banda, Latencia y Throughput
Conceptos clave para medir y entender una conexion
▼

Tres metricas se confunden siempre. Saber distinguirlas explica por que "mi plan es de 300 Mbps pero se siente lento".

MetricaDefinicionUnidadAnalogia
Ancho de bandaCapacidad maxima teorica del enlaceMbps, GbpsAncho de una autopista
LatenciaTiempo de ida y vuelta (RTT) de un datomsTiempo de viaje por la autopista
ThroughputVelocidad real transferidaMbpsAutos que realmente pasan
JitterVariacion de la latencia entre paquetesmsGolpes de freno en el trafico
Perdida de paquetes% de paquetes que no llegan%Autos que se pierden en el camino
¿Que afecta a que? Descargar un archivo depende del ancho de banda/throughput. Jugar online y VoIP dependen de la latencia y el jitter. Una conexion con 200 Mbps pero 150ms de latencia es mala para gaming aunque buena para descargas.
Medir latencia y perdida (Windows / Linux)
> ping -t 8.8.8.8            # Latencia continua (Ctrl+C para detener)
$ ping -c 50 8.8.8.8         # Linux: 50 paquetes y estadisticas
> pathping 8.8.8.8           # Latencia por salto (Windows)
Half Duplex vs Full Duplex
Un solo sentido vs ambos · CSMA/CD vs CSMA/CA
▼
CaracteristicaHalf DuplexFull Duplex
DireccionUn solo sentido a la vez (walkie-talkie)Ambos sentidos simultaneos (telefono)
ColisionesPosibles (CSMA/CD)Inexistentes (cada par de hilos es dedicado)
Velocidad efectivaLa mitad de la nominalNominal completa en cada sentido
Uso actualObsoleto en LAN cableadasEstandar en switch ↔ PC moderno
CSMA/CD vs CSMA/CA Ethernet usa CSMA/CD (Carrier Sense Multiple Access with Collision Detection): escucha, transmite y si detecta colision retrocede y reintenta. Wi-Fi usa CSMA/CA (Collision Avoidance): escucha y espera un tiempo aleatorio ANTES de transmitir para evitar la colision, porque en radio no puede "sentir" la colision mientras transmite.
