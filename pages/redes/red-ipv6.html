IPv4/IPv6

// Del agotamiento de IPv4 a las 128 bits de IPv6, con todo lo que cambia

IPv6 reemplaza a IPv4 porque las direcciones de 32 bits se agotaron. Usa 128 bits: hay direcciones de sobra para cada dispositivo, incluso IoT.
Notacion y abreviaciones
  • Se escribe en 8 grupos de 4 digitos hexadecimales separados por :: 2001:0db8:0000:0000:0000:ff00:0042:8329.
  • Se omiten los ceros iniciales de cada grupo: 0042 → 42.
  • Una secuencia de grupos en cero se comprime con :: (una sola vez): 2001:db8::ff00:42:8329.
  • Preferencia: usa minusculas, no comprimas :: dos veces (seria ambiguo).
Ejemplo: fe80::1 es la forma corta de fe80:0000:0000:0000:0000:0000:0000:0001.

No existe broadcast en IPv6: se usa multicast. Y no hay direcciones privadas como en IPv4: la privacidad se maneja con ULA y direcciones temporales.
Prefijos y subredes
  • Un prefijo es la parte fija de la direccion. Se escribe como CIDR: 2001:db8::/32.
  • Los ISP suelen entregar un /48 o /56 para tu red; cada red LAN usa un /64 (estandar).
  • Un /64 tiene 2^64 direcciones: mas que todos los granos de arena de la Tierra.
  • La parte de los 64 bits restantes es el Interface ID (identifica el dispositivo en la subred).
La notacion CIDR y el calculo de subredes se explican en Direccionamiento IP.
Autoconfiguracion: SLAAC y DHCPv6
  • SLAAC: el router anuncia el prefijo (RA) y cada equipo genera su propia direccion (EUI-64 o aleatoria). Sin servidor DHCP.
  • DHCPv6: entrega direcciones y otros parametros como en IPv4, opcional en IPv6.
  • Los equipos usan direcciones temporales (privacidad): cambian periodicamente para no rastrear al usuario.
  • Por defecto todo equipo IPv6 tiene una link-local fe80:: aunque no haya red configurada.
Ver IPv6 en tu equipo
cmd — ver IPv6 en Windows
> ipconfig
  > netsh interface ipv6 show addresses
  > ping -6 google.com
bash — ver IPv6 en Linux
$ ip -6 addr
  $ ping6 google.com
  • ping -6 / ping6: prueba conectividad IPv6.
  • Verifica si tienes IPv6 en tu conexion con sitios de test (ej. test-ipv6).
Coexistencia con IPv4: dual stack
  • Dual stack: el equipo tiene IPv4 e IPv6 a la vez; cada conexion elige el protocolo disponible. Es la forma estandar de transicion.
  • Tuneles (6to4, Teredo, ISATAP): encapsulan IPv6 dentro de IPv4 cuando no hay IPv6 nativo. Hoy en desuso por problemas de rendimiento y seguridad.
  • NAT64/DNS64: permiten que equipos solo-IPv6 accedan a recursos solo-IPv4 (comun en moviles).
  • DNS: un registro AAAA apunta a una IPv6 (ver DNS).
Si tu proveedor te da IPv6, dejala activa en el router y en el equipo: muchas veces mejora la velocidad y la latencia de los sitios compatibles.

En la practica: hoy conviven ambos (dual stack). Tu equipo casi seguro tiene IPv4 e IPv6 a la vez; el sistema elige el mejor camino disponible para cada conexion.
Cabecera IPv6 — estructura del paquete
  • Version (4 bits): siempre 6.
  • Traffic Class (8 bits): prioridad / calidad de servicio (DSCP y ECN).
  • Flow Label (20 bits): etiqueta para que los routers traten los paquetes de un mismo flujo de forma uniforme.
  • Payload Length (16 bits): tamano en bytes de la carga util (sin contar los 40 de la cabecera).
  • Next Header (8 bits): que sigue: TCP (6), UDP (17), ICMPv6 (58), OSPF (89) o una cabecera de extension.
  • Hop Limit (8 bits): igual que el TTL de IPv4; se decrementa en cada salto.
  • Direccion de origen (128 bits) y direccion de destino (128 bits).
CampoIPv4IPv6
Tamano de cabecera20 bytes (con opciones, variable)40 bytes fijos
IHL / longitudCampo IHL variableFija; solo se agregan cabeceras de extension

Resultado: una cabecera mas simple que los routers procesan mas rapido, sin checksum que recalcular ni fragmentacion que gestionar.
Interface ID y EUI-64
  • El Interface ID son los 64 bits bajos de la direccion: identifican al dispositivo dentro de su /64.
  • Metodo clasico EUI-64: se toma la MAC (48 bits), se inserta ff:fe en el medio y se invierte el bit 7 (bit U/L). Ejemplo: 00:1a:2b:3c:4d:5e → 021a:2bff:fe3c:4d5e.
  • Por privacidad (RFC 4941), la mayoria de sistemas operativos generan direcciones temporales aleatorias que rotan periodicamente y usan para salir a Internet.
  • EUI-64 de MAC publica permite rastrear al dispositivo; por eso se usa direccion aleatoria, no la derivada de la MAC.
ejemplo — derivar EUI-64 de una MAC
# MAC 00:1a:2b:3c:4d:5e
> paso 1: insertar ff:fe → 00:1a:2b:ff:fe:3c:4d:5e
> paso 2: invertir bit 7 → 02:1a:2b:ff:fe:3c:4d:5e
> resultado: 2001:db8::021a:2bff:fe3c:4d5e/64
ICMPv6 y Neighbor Discovery (NDP)
  • ICMPv6 es el protocolo de control de IPv6: ademas de las funciones de ping (echo request/reply) y errores, hace las tareas que en IPv4 hacian ARP, IGMP y el descubrimiento de routers.
  • Router Solicitation (RS) / Router Advertisement (RA): el equipo pide el prefijo y el router lo anuncia (base de SLAAC).
  • Neighbor Solicitation (NS) / Neighbor Advertisement (NA): resuelve la direccion MAC de un vecino — reemplaza a ARP.
  • DAD (Duplicate Address Detection): antes de usar una direccion, verifica que nadie mas la este usando.
  • Redirect: el router avisa al host de una ruta mejor (por ejemplo, otro router en la misma LAN).
bash — ver la tabla de vecinos (equivalente a ARP)
$ ip -6 neigh
$ ping6 fe80::1   # antes resuelve el vecino via NS/NA
Dato: los mensajes NDP usan la direccion multicast solicited-node en vez de broadcast, lo que no molesta a todos los equipos de la red.
