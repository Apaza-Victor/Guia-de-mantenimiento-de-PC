DNS

// Domain Name System: traduce nombres a IPs

DNS convierte nombres que recuerdas (p. ej. ejemplo.com) en direcciones IP que las redes entienden. Es el sistema de nombres distribuido de internet.
Que es y como funciona
  • Funciona como una base de datos distribuida: ningun servidor tiene toda la info, se consulta en cadena.
  • Es jerarquico: dominio raiz (.), TLD (.com, .net, .org), dominio (ejemplo.com) y subdominios (www, mail).
  • Las consultas viajan por UDP/TCP puerto 53 (UDP por defecto).
  • La respuesta tiene un TTL (tiempo de vida): la informacion se guarda en cache local y deja de valer al expirar.

Los registros MX y SPF/DKIM son lo que hace que el correo llegue y no caiga en spam. Si un cliente dice "no recibe correos", revisa el DNS primero.
Proceso de resolucion
  1. Tu equipo consulta su resolver (generalmente el DNS de tu router o proveedor).
  2. Si el resolver no tiene la respuesta en cache, consulta a un servidor raiz (.).
  3. El raiz responde con los servidores del TLD (.com).
  4. El TLD responde con los servidores autoritativos del dominio (NS).
  5. El servidor autoritativo devuelve el registro A/AAAA pedido.
  6. El resolver guarda la respuesta en cache (segun TTL) y tu equipo se conecta a la IP.
En la practica el proceso tarda milisegundos porque la cache evita repetir toda la cadena. El recursive resolver hace el trabajo pesado por tu equipo.

Comandos utiles
cmd — consultar y vaciar cache DNS
> nslookup ejemplo.com
  > nslookup -type=MX ejemplo.com
  > ipconfig /flushdns
  > ipconfig /displaydns
bash — dig y host (Linux/macOS)
$ dig ejemplo.com
  $ dig ejemplo.com MX
  $ host ejemplo.com
  • nslookup / dig: consultan un servidor DNS especifico o por defecto.
  • ipconfig /flushdns: vacia la cache local de Windows (util tras un cambio de DNS).
  • Para forzar el servidor de consulta: nslookup ejemplo.com 8.8.8.8.
Problemas comunes de DNS
ProblemaSolucion
"El servidor DNS no responde"Reinicia router/modem, cambia a un DNS publico, verifica que el servicio DNS funcione.
Sitio no resuelve en un equipo pero si en otrosVacia la cache (ipconfig /flushdns), revisa el archivo hosts, cambia DNS del adaptador.
DNS cache poisoning / hijackingUsa DNSSEC si es posible, cambia DNS a uno confiable, evita redes con DNS manipulados.
Correo no llegaVerifica registros MX, SPF/TXT, DKIM y DMARC del dominio con dig -t MX.
DNS apunta a una IP viejaEspera el TTL (propagacion) o consulta con un DNS sin cache para verificar.
Filtrado de contenidos del proveedorCambia el DNS del router o equipo a uno publico (donde sea legal).
El archivo hosts (Windows: C:\Windows\System32\drivers\etc\hosts, Linux: /etc/hosts) tiene prioridad sobre el DNS: se usa para mapeos manuales y bloqueos locales.
