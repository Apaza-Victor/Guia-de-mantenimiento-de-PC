Laboratorio de Practicas

// La teoria se aprende simulando

Herramienta: Cisco Packet Tracer es un simulador gratuito de redes con PCs, switches y routers que funcionan de verdad. Permite configurar con la CLI real de Cisco sin gastar un centavo en hardware.
Instalacion y primeros pasos
Obtener e instalar Packet Tracer
▼
  1. Descarga Packet Tracer desde NetAcad (netacad.com) — requiere cuenta gratuita, o usa la version para descarga directa segun tu curso.
  2. Instala y abre; en la pestana Logical vas a construir la red arrastrando dispositivos.
  3. Dispositivos clave en la barra inferior: End Devices (PC, laptop, servidor) y Network Devices (switch 2960, router 2911).
  4. Para conectar: elige el cable de cobre directo (Copper Straight-Through) para PC↔switch y switch↔router (aunque PT permite auto-mdix).
  5. Haz click en un PC → Desktop → IP Configuration para poner IP manual, o Command Prompt para usar ping/ipconfig.
Practica 1 — Dos PCs conectados directos
Lo mas basico: cable, IP y ping
▼
  1. Arrastra 2 PCs al area de trabajo.
  2. Conectalos con cable Copper Cross-Over (o Straight-Through, PT lo acepta) entre las tarjetas FastEthernet.
  3. Configura IPs: PC0 → 192.168.1.1/24; PC1 → 192.168.1.2/24.
  4. Abre Command Prompt en PC0 y ejecuta ping 192.168.1.2.
  5. Debe responder. Cambia a modo Simulation y envia de nuevo el ping: veras los paquetes ICMP viajar como sobres entre capas.
Objetivo didactico: entender que sin IP en la misma subred no hay comunicacion, y ver el recorrido fisico de los paquetes en el modo simulacion (event list + animacion).
Practica 2 — Conectados con un switch
El switch no necesita configuracion para esto
▼
  1. Agrega un Switch 2960 y 3 PCs.
  2. Conecta cada PC al switch con cable directo.
  3. Asigna IPs de la misma subred (192.168.1.x) a los 3 PCs.
  4. Haz ping de un PC a otro y comprueba que responden (el switch aprende MACs solo).
  5. Revisa la MAC address table del switch: CLI → show mac address-table y observa como cada puerto asocio una MAC.
Practica 3 — Router con dos subredes
Inter-VLAN / inter-subred routing
▼
  1. Arma: PC A → Switch 1 → Router 2911 → Switch 2 → PC B.
  2. Configura en el router: int Gig0/0 ip address 192.168.10.1 255.255.255.0 no shutdown; int Gig0/1 ip address 192.168.20.1 255.255.255.0 no shutdown.
  3. PC A: IP 192.168.10.10/24, gateway 192.168.10.1. PC B: IP 192.168.20.10/24, gateway 192.168.20.1.
  4. Ping de PC A a PC B (192.168.20.10): debe funcionar GRACIAS al gateway.
  5. Prueba sin gateway: quita la puerta de enlace y repite el ping → no responde. Ese es el concepto de routing.
Practica 4 — VLAN y trunk
Segmenta y conecta switches
▼
  1. Dos switches, 4 PCs (2 por switch).
  2. Crea VLANs: vlan 10 name Ventas; vlan 20 name RRHH (en ambos switches).
  3. Puertos hacia PCs: switchport mode access + switchport access vlan 10 (o 20).
  4. Enlace entre switches: switchport mode trunk + switchport trunk allowed vlan 10,20.
  5. Verifica: PCs de la misma VLAN se ven entre si (ping); PCs de VLAN distinta NO (sigue la practica 5 para comunicarlos).
Practica 5 — Router-on-a-stick y DHCP
Comunica VLANs y reparte IPs
▼
  1. Sobre la practica 4, conecta el router al switch con un solo cable (trunk en el puerto del switch).
  2. Subinterfaces en el router: int Gig0/0.10 encapsulation dot1Q 10 ip address 192.168.10.1 255.255.255.0; repite con .20.
  3. Configura DHCP por subinterfaz: ip dhcp pool Ventas network 192.168.10.0 255.255.255.0 default-router 192.168.10.1; igual para RRHH.
  4. En los PCs pon "IP Configuration → DHCP". Veras que reciben IP automatica del pool correspondiente.
  5. Haz ping entre VLANs: PC Ventas → PC RRHH. Ahora si, porque el router enruta (permitido).
Regla: al final, reflexiona: "sin inter-VLAN routing las VLANs estan aisladas; al agregar el router, se comunican". Si quieres bloquear ese trafico, ver el tema de ACLs en la practica extra.
Practica 6 — Routing estatico entre routers
Dos routers, rutas manuales
▼
  1. Dos routers unidos por un enlace serial (o Gigabit). R1 a la subred A (192.168.1.0/24), R2 a la subred B (192.168.2.0/24).
  2. Configura IPs en los enlaces entre routers (ej. 10.0.0.0/30: R1 .1, R2 .2).
  3. Ruta estatica en R1 hacia B: ip route 192.168.2.0 255.255.255.0 10.0.0.2. En R2 hacia A: ip route 192.168.1.0 255.255.255.0 10.0.0.1.
  4. Ping de un PC de la subred A a uno de la B: funciona solo con ambas rutas.
  5. Borra una ruta y repite: veras "Destination host unreachable" — asi entiendes por que las rutas deben estar en ambos sentidos.
Extensiones del laboratorio: repeti las practicas con GNS3/EVE-NG (maquinas reales), agrega ACLs para bloquear trafico, configura OSPF en vez de rutas estaticas, y monta NAT para que una LAN salga a internet.
