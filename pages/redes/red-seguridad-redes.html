Seguridad de Red

// Autentica, autoriza y controla el acceso

Concepto: en una red corporativa no basta con WPA2/WPA3. Hay que saber QUIEN accede, con QUE derechos y QUE hizo. Eso es exactamente lo que resuelve el modelo AAA.
AAA — Autenticacion, Autorizacion y Contabilidad
El modelo de control de acceso
▼
ComponenteQue respondeEjemplo
AutenticacionQuien eresUsuario + contrasena, certificado, token
AutorizacionQue puedes hacerNivel de acceso (usuario, admin, VLAN asignada)
ContabilidadQue hiciste y cuandoLogs de sesion, tiempo conectado, consumo
  • Implementacion tipica: el switch/router (autenticador) reenvia las credenciales a un servidor central (RADIUS/TACACS+) que autentica contra un directorio (Active Directory, LDAP).
  • Beneficio: si alguien cambia de contrasena o es despedido, se le revoca el acceso desde UN solo lugar, no desde cada equipo de red.
RADIUS vs TACACS+
Los dos protocolos AAA, cuando usar cada uno
▼
CriterioRADIUSTACACS+
EncriptacionSolo la contrasenaTodo el paquete (total)
ProtocoloUDP (1812/1813)TCP (49)
Separa auth/author/accountingUn solo paquete para todoSi, por separado (mas granular)
Uso tipicoAcceso de usuarios finales (Wi-Fi, VPN, 802.1X)Administracion de dispositivos de red (SSH)
En la practica: RADIUS domina en autenticacion de usuarios de red (es el estandar para Wi-Fi empresarial y VPN). TACACS+ (Cisco) es preferido para controlar quien administra los switches/routers. Un buen entorno suele usar ambos.
802.1X — el estandar de acceso por puerto
Suplicante · Autenticador · Servidor
▼
  • Suplicante: el dispositivo que pide acceso (PC, telefono) con su credencial o certificado.
  • Autenticador: el switch o punto de acceso que deja pasar el trafico SOLO si la autenticacion funciona.
  • Servidor de autenticacion: RADIUS (ej. FreeRADIUS, NPS de Windows) que decide y devuelve la VLAN asignada.
  • Antes de autenticar, el puerto solo permite tramas EAP (protocolo de autenticacion) — nada de trafico normal.
  • Util en redes cableadas (evita que alguien conecte una laptop a un puerto y obtenga red) y Wi-Fi empresarial.
Ejemplo Wi-Fi: con WPA2/3-Enterprise (802.1X + RADIUS), cada usuario ingresa su usuario/contrasena de la empresa en lugar de una clave Wi-Fi compartida. Se puede revocar acceso individual al instante.
Metodos EAP
PEAP, EAP-TLS y compania
▼
Metodo EAPComo autenticaSeguridad
PEAP (EAP-MSCHAPv2)Usuario + contrasena dentro de un tunel TLS hacia el servidorBuena (si se valida el certificado del servidor)
EAP-TLSCertificados digitales en CLIENTE y servidorExcelente (sin contrasenas que robar)
EAP-TTLSSimilar a PEAP, con mas flexibilidadBuena
EAP-MD5 / LEAPContrasena simpleDebil — NO usar
Recomendacion: EAP-TLS con certificados por dispositivo es el mas seguro (ideal para empresas con gestion de certificados tipo Intune/AD CS). PEAP con contrasenas es el mas practico para empezar; exige validar el certificado del servidor para evitar "evil twin".
FreeRADIUS basico
Pon a prueba 802.1X en un lab
▼
  1. Instala FreeRADIUS: apt install freeradius (Debian/Ubuntu).
  2. Anade un cliente: en clients.conf, define la IP del switch/AP y el secreto compartido.
  3. Anade un usuario de prueba en users o en mods-available/sql (base de datos).
  4. Prueba manualmente: radtest usuario pass 127.0.0.1 0 secreto.
  5. En el switch, configura el puerto 802.1X apuntando al servidor RADIUS (IP, secreto) y el metodo (dot1x pae authenticator, aaa authentication dot1x default group radius).
  6. Prueba conectando una laptop con supplicant (Windows "Autenticacion de red 802.1X" o wpa_supplicant en Linux).
Logs: si la autenticacion falla, revisa /var/log/freeradius/radius.log. La causa mas comun es un secreto compartido distinto entre switch y servidor, o credenciales incorrectas.

Mejores practicas resumidas
La checklist del administrador
▼
  • Cambia contrasenas por defecto de TODOS los equipos de red.
  • Usa RADIUS para acceso de usuarios (Wi-Fi/VPN/802.1X) y TACACS+ para administracion.
  • Segmenta con VLANs y limita el inter-VLAN con ACLs.
  • Activa 802.1X en puertos de oficina y WPA3-Enterprise en Wi-Fi.
  • Combina Port Security, DHCP Snooping y DAI en los switches de acceso.
  • Desactiva servicios no usados (SNMP v1/v2c con default, telnet, UPnP).
  • Actualiza firmware y certificados (no dejes expirar los CA de 802.1X).
  • Registra y monitorea logs de acceso e intrusiones.
