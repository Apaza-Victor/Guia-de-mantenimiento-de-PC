NAT y Port Forwarding

// Como una sola IP publica sirve a toda la red interna

NAT (Network Address Translation) traduce las IPs privadas de tu red a la IP publica del router y viceversa. Es el motivo por el que todos tus dispositivos salen a internet "como uno solo".
Que es y por que existe
  • Por que existe: las IPs IPv4 son limitadas; el NAT permite que miles de equipos compartan una sola IP publica.
  • Seguridad adicional: los equipos internos no son directamente alcanzables desde internet; el router solo permite las conexiones que el establecio (o las reenvia a peticion).
  • Las IPs privadas (10.x, 172.16-31.x, 192.168.x) NO viajan por internet: el router las traduce.
  • El NAT mantiene una tabla de traduccion (puerto/IP interna ↔ IP publica/puerto) para saber a quien devolver cada paquete.

El PAT (Port Address Translation) es el motivo de que "el puerto este cerrado": el router distingue conexiones por puerto, y sin reglas no sabe a que equipo interno reenviar las conexiones entrantes.
Port Forwarding (reenvio de puertos)

El port forwarding le dice al router: "las conexiones que lleguen al puerto X de mi IP publica, reenviarlas al equipo interno 192.168.x.y puerto Z". Sirve para servidores web, camaras IP, juegos, SSH, etc.

Pasos para configurarlo

  1. Asigna una IP fija al equipo destino (reserva DHCP o estatica).
  2. Entra al router (ej. 192.168.1.1) → seccion "Port Forwarding" / "Virtual Server" / "Reenvio de puertos".
  3. Crea la regla: puerto externo (ej. 8080), IP interna (ej. 192.168.1.50) y puerto interno.
  4. Define el protocolo (TCP, UDP o ambos) segun la aplicacion.
  5. Guarda y verifica desde afuera de tu red.
Seguridad: exponer un puerto es abrir una puerta de tu red. Solo reenvia los puertos necesarios, apunta a la IP correcta y usa autenticacion fuerte en el servicio expuesto.
DMZ, UPnP y port triggering
  • DMZ: expone UN equipo interno completamente (todos sus puertos) hacia internet. Comoda pero peligrosa: usala solo temporalmente o en zonas aisladas.
  • UPnP / NAT-PMP: las aplicaciones abren puertos solas en el router. Comodo (juegos, consolas) pero un riesgo si el router es de dudosa calidad. Desactivalo si no lo necesitas.
  • Port triggering: abre un puerto automaticamente cuando detecta trafico saliente en otro. Util para aplicaciones con puertos dinamicos.
Preferencia segura: port forwarding puntual y con IP fija, sobre la DMZ y sobre UPnP.
Doble NAT
  • Que es: cuando hay dos routers haciendo NAT en serie (ej. un router del ISP + tu router propio).
  • Problemas: el port forwarding falla (hay que configurarlo en los dos), los juegos peer-to-peer tienen problemas y aparecen "IP privada" al consultar tu IP.
  • Como detectarlo: entra a la pagina del router 2 y compara su IP WAN: si es privada (192.168.x / 10.x), hay doble NAT.
  • Soluciones: pon tu router en modo bridge (o modo AP) para que solo el router del ISP haga NAT; o configura port forwarding en ambos routers.
En modo bridge el router propio pierde sus funciones de router (WiFi sigue activo como AP). La alternativa mas limpia para una red hogarena es un solo equipo con NAT.
Verificar y troubleshooting
  • Consulta tu IP publica (en el router o en sitios de "cual es mi IP") para probar desde afuera.
  • Prueba el puerto abierto con herramientas web de "port checker" o con Test-NetConnection en PowerShell.
  • Si el puerto figura cerrado: revisa el doble NAT, el firewall del equipo destino y que el servicio escuche en la IP correcta.
  • Para servicios locales, conecta primero desde la red interna; si funciona ahi, el problema es el reenvio.
powershell — probar un puerto remoto
PS> Test-NetConnection mi-ip-publica -Port 8080
