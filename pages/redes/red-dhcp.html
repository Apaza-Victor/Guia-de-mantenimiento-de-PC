DHCP

// Dynamic Host Configuration Protocol

DHCP asigna automaticamente a cada dispositivo su direccion IP, mascara, puerta de enlace, DNS y mas. Sin el, habria que configurar cada equipo a mano.
Como funciona: el proceso DORA
  1. Discover: el cliente difunde un mensaje buscando un servidor DHCP (UDP 67/68, broadcast).
  2. Offer: el servidor responde ofreciendo una IP y parametros.
  3. Request: el cliente solicita formalmente esa oferta.
  4. Ack: el servidor confirma y entrega la concesion (lease).
Si hay varios servidores DHCP (por ejemplo un router de mas conectado), el cliente acepta solo una oferta; de ahi los problemas de IP erronea o "sin internet" en redes mal configuradas.
Concesiones y renovacion
  • La concesion (lease) tiene una duracion (ej. 24 h en hogar, horas en WiFi publico).
  • En T1 (50% de la concesion) el cliente pide renovarla; en T2 (87%) si no respondio, la vuelve a pedir.
  • Si la concesion expira sin renovar, el cliente pide una IP nueva desde cero.
  • Renovar/liberar en Windows: ipconfig /release y ipconfig /renew.
cmd — renovar concesion DHCP
> ipconfig /release
  > ipconfig /renew
IP estatica vs DHCP y reservas
OpcionComo funcionaCuando usarla
DHCP dinamicoEl servidor entrega IPs de un rango (scope)Equipos de usuario, dispositivos moviles
Reserva DHCPIP fija por MAC dentro del servidor DHCPImpresoras, servidores, equipos que necesitan IP estable
IP estatica manualSe configura en el propio equipoServidores, equipos de red, cuando no hay DHCP
La reserva es preferible a la IP estatica manual: el servidor DHCP no asigna esa IP a otro equipo y es mas facil de administrar. La estatica manual fuera del rango del DHCP evita conflictos.
Configurar un servidor DHCP

En el router (lo mas comun en hogar/PyME)

  • Activa DHCP en la red LAN y define el rango (scope): p. ej. 192.168.1.100 a 192.168.1.200.
  • Configura la puerta de enlace (la IP del router) y el DNS.
  • Usa reservas por MAC para los equipos que necesitan IP fija.

En Windows Server / Linux

  • Windows Server: rol DHCP, crea un scope, define exclusiones y reservas.
  • Linux (dnsmasq / ISC DHCP): dhcp-range y opciones por red en la config.
  • Nunca dos servidores DHCP para la misma red sin reglas claras: genera IPs conflictivas.
Troubleshooting DHCP
ProblemaSolucion
IP 169.254.x.x (APIPA)El equipo no recibio IP: el DHCP no respondio. Verifica cable/red, reinicia router, renueva la concesion.
"IP en conflicto"Dos equipos con la misma IP: renueva, revisa reservas duplicadas o estaticas manuales dentro del rango.
Scope agotadoAmplia el rango o reduce la duracion de concesion; revisa IPs reservadas sin uso.
IP que cambia todo el tiempoUsa una reserva DHCP para ese equipo (impresora, servidor).
Rogue DHCP (IP de un router extra)Detectalo con ipconfig /all (ver el DHCP server asignado) y desactiva DHCP en el router intruso.
La IP 169.254.x.x es la autoconfigurada (APIPA): no es la del router. Si la ves, el DHCP fallo: la causa suele estar en el servidor DHCP o en el cable.
